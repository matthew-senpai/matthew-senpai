<details>
<summary><b>🛰️ Landsight — AI landslide survivor detection & rescue coordination</b></summary>
<br/>

Drone footage goes in; a rescue command center comes out. People are detected, geolocated, tracked on the ground, deduplicated and ranked with a transparent points table, and every survivor comes with evidence.

**Pipeline**

`Drone video + MAVLink telemetry` → `Person detection (replay / YOLO)` → `Geolocation` → `Ground-plane tracking` → `Analysis & dedup` → `Priority: HIGH / MEDIUM / LOW` → `Evidence + SQLite` → `FastAPI` → `React command center + Leaflet map`

| | |
|---|---|
| **Stack** | Python · FastAPI · NumPy · React 19 · TypeScript · Vite · Tailwind CSS · Leaflet · YOLO (optional) |
| **Results** | Sample mission: 12/12 people found · 0 duplicate survivors · ≈ 0.65 m mean location error (target ≤ 5 m) |
| **Key idea** | Geolocate *before* tracking: the drone moves ~1 m per frame, so image-space matching falls apart for small people; matching on the ground keeps tracks stable |
| **Status** | Software-first prototype; the drone (MAVLink / RTSP) integration code is written but not yet flight-tested |
| **Links** | [Live demo](https://survivor-detector.vercel.app) · [Repository](https://github.com/matthew-senpai/Survivor_Detector) |

</details>

<details>
<summary><b>💊 RCCP — Pharma Reverse Chain Compliance Platform</b></summary>
<br/>

Tracks expired medicines from retail shelf to verified destruction across retailer, distributor, manufacturer and biomedical-waste-facility roles. Every handoff is a quantity claim checked against an append-only ledger, so each way of slipping expired stock back into circulation breaks a rule.

**Request path**

`Role dashboards + public batch lookup` → `API routes (Zod validation, auth)` → `Domain core: 8 invariants as pure functions` → `Append-only ledger` → `Audit hash chain` → `PostgreSQL via Prisma (one transaction per mutation)`

| Fraud attempt | What catches it |
|---|---|
| Reuse a destroyed batch number | Registry status is `DESTROYED` → blocked at the point of sale |
| Clone another real batch number | Units billed exceed units issued → critical alert |
| Invent a batch number | Not in the registry → critical alert |

| | |
|---|---|
| **Stack** | Next.js 14 (App Router) · React 18 · TypeScript (strict) · Tailwind CSS · PostgreSQL (Neon) · Prisma · Zod · JWT (jose) · Vitest |
| **Testing** | Invariant, lifecycle and audit-chain unit tests, plus an HTTP-driven acceptance script that checks the business rules end-to-end |
| **Links** | [Live demo](https://pharma-trace-nine.vercel.app) · [Repository](https://github.com/matthew-senpai/Pharma-Trace) |

</details>

<details>
<summary><b>🧩 S.E.E.D — System for Early Detection and Development</b></summary>
<br/>

An AI screening platform for early autism risk in children aged 2–5. Game modules and an M-CHAT-R/F questionnaire collect behaviour signals, a queued analysis engine scores them against age-group baselines, and a clinician reviews every result. Presented at hackathons and paper presentations.

**Screening flow**

`Clinician invite code (DPDP Act 2023 consent gate)` → `Child profile + session (Express API)` → `Phaser 3 games + M-CHAT-R/F` → `Bull queue on Redis` → `FastAPI: MediaPipe landmarks → features → XGBoost` → `Live results via Socket.io` → `Clinician review & override`

| | |
|---|---|
| **Stack** | React 18 · TypeScript · Tailwind CSS · Phaser 3 · Node.js · Express · Prisma · PostgreSQL · Redis · FastAPI · MediaPipe · XGBoost · Docker Compose |
| **Design** | No "low risk" tier: results are MONITOR, INDETERMINATE or ELEVATED, so the system never clears a child outright. One metric more than 2 SD below the norm lifts the result to at least INDETERMINATE |
| **Honesty** | A screening aid, not a diagnosis; age-group baselines are marked approximate until validated on an Indian cohort |
| **Links** | [Repository](https://github.com/matthew-senpai/SEED) |

</details>

<details>
<summary><b>🎯 Smart Attendance System — RFID + face verification + anomaly detection</b></summary>
<br/>

An RFID attendance kiosk that a handed-over card can't fool. Each tap is paired with a face check, cross-checked for impossible travel between rooms, written locally first so outages never lose data, and turned into an explainable per-student risk score.

**From tap to dashboard**

`RFID tap + face embedding` → `Anti-proxy check (cosine similarity)` → `Impossible-travel detection (haversine + max speed)` → `Local SQLite store (offline-first)` → `Background sync` → `Risk analytics` → `Flask API + dashboard`

| | |
|---|---|
| **Stack** | Python · Flask 3 · NumPy · SQLite (local) · PostgreSQL via psycopg (production) · Jinja · JavaScript · pytest · Vercel |
| **Design** | Two independent signals: the face match stops proxies, the travel check catches photo spoofing · Offline-first, so a Wi-Fi outage never loses attendance · Every entry stored with a second-precision timestamp |
| **Hardware** | Runs in simulation mode out of the box; a real ESP32 / Raspberry Pi kiosk replaces a single module, and rooms, classes and thresholds live in one JSON config |
| **Links** | [Repository](https://github.com/matthew-senpai/SMART-ATTENDANCE-SYSTEM) |

</details>
